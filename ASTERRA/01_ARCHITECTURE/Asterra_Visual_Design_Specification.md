# 1. Purpose

This document defines the visual direction for Asterra's website.

It translates the approved design architecture into a more concrete visual language while keeping the system flexible enough for the individual page specifications.

The objective is to create an experience that communicates:

> **Corporate authority, technical capability, credibility, and modern professionalism.**

The design should feel established and premium without becoming overly luxurious or decorative.

---

# 2. Core Visual Direction

Asterra should combine:

```text
Corporate Authority
        +
Editorial Composition
        +
Technical Precision
        +
Strong Photography
        +
Controlled Minimalism
```

The result should feel:

* Mature
* Confident
* Structured
* Contemporary
* Professional
* Human
* Evidence-driven

Avoid making the website resemble:

* A generic consulting template
* A SaaS landing page
* A government portal
* An overly luxurious hotel website
* A technology startup website

---

# 3. Visual Personality

The visual personality should be:

### Confident

Large, clear headlines and decisive layouts.

### Precise

Strong alignment, consistent spacing, restrained decoration.

### Sophisticated

Editorial typography and carefully selected imagery.

### Accessible

Readable content, obvious interaction, strong contrast.

### Human

Real people, projects, places, and organizational evidence should be visible wherever appropriate.

---

# 4. Color Direction

The final Asterra brand colors should take priority if official brand assets or guidelines are available.

The visual system should nevertheless maintain the following semantic structure:

```text
PRIMARY
Main corporate identity

SECONDARY
Supporting corporate tone

ACCENT
Calls attention to important actions or information

LIGHT BACKGROUND
Primary content surfaces

DARK BACKGROUND
High-impact sections

TEXT
Primary / Secondary / Muted

BORDER
Structural separation
```

---

# 5. Recommended Color Behavior

Rather than using many colors, Asterra should rely on **contrast and tonal hierarchy**.

A typical section may use:

```text
Light Background
      ↓
Dark Typography
      ↓
Controlled Accent
```

A high-impact section may invert this:

```text
Dark Background
      ↓
Light Typography
      ↓
Accent Detail
```

Accent color should be used sparingly.

It should not become the dominant visual color of the website.

---

# 6. Typography Direction

Typography should be one of Asterra's major differentiators.

The system should use a strong hierarchy between:

```text
Display
H1
H2
H3
Body
Navigation
Labels
Metadata
```

The final font pairing should be selected during implementation/design exploration, but the visual direction should favor:

**A distinctive editorial display face + highly readable supporting typeface**

or:

**One strong contemporary typeface with carefully controlled weights.**

Avoid generic typography that makes the website visually interchangeable with common corporate templates.

---

# 7. Display Typography

Large headlines should be:

* Strong
* Spacious
* Controlled
* Short where possible
* Visually dominant

Example hierarchy:

```text
EYEBROW

Engineering a stronger future.

Supporting statement explaining
Asterra's role and capability.
```

Large display typography should not be used simply because the screen is large.

It must support the communication hierarchy.

---

# 8. Body Typography

Body text should prioritize readability.

Recommended characteristics:

* Comfortable line height
* Moderate line length
* Clear paragraph separation
* Strong contrast
* Responsive sizing

Long-form Insights content should use a narrower reading measure than general corporate content.

---

# 9. Navigation Typography

Navigation should be:

* Clear
* Compact
* Highly readable
* Visually subordinate to major page headlines

Avoid oversized navigation that competes with the content.

Navigation labels should remain simple:

```text
About
Business
Projects
Insights
Careers
Contact
```

---

# 10. Label / Eyebrow Style

Small labels can provide hierarchy and editorial character.

Example:

```text
BUSINESS CAPABILITIES
```

or:

```text
SELECTED PROJECTS
```

They should use:

* Controlled letter spacing
* Strong contrast
* Consistent capitalization
* Small but readable size

Do not use tiny text that becomes inaccessible.

---

# 11. Layout Character

Asterra should favor **structured asymmetry** rather than perfectly repetitive layouts.

Example:

```text
┌───────────────────────┬──────────────┐
│                       │              │
│      LARGE TITLE      │    IMAGE     │
│                       │              │
│      Supporting       │              │
│      information      │              │
│                       │              │
└───────────────────────┴──────────────┘
```

This can be balanced by:

* Grid alignment
* Consistent margins
* Repeated spacing
* Strong typography

The layout should feel intentional rather than chaotic.

---

# 12. Container Width

The primary content area should not stretch unnecessarily across very large screens.

Use a controlled maximum width:

```text
┌──────────────────────────────────────────┐
│                                          │
│             ASTERRA CONTENT              │
│                                          │
└──────────────────────────────────────────┘
```

Some visual sections, especially hero imagery, may intentionally extend beyond the standard content container.

---

# 13. Whitespace

Whitespace should be a major part of the design language.

Use generous spacing around:

* Major headlines
* Section transitions
* Large images
* Editorial content
* Important CTAs

Whitespace should communicate confidence rather than emptiness.

---

# 14. Section Transitions

Sections should have enough visual distinction to help visitors understand the page structure.

Methods may include:

* Background changes
* Typography scale
* Image placement
* Grid changes
* Borders
* Spacing

Avoid adding decorative shapes to every section.

---

# 15. Homepage Visual Direction

The homepage should have the strongest visual impact.

Recommended sequence:

```text
HERO
Large statement + strong visual

↓

CORPORATE INTRO
Editorial text composition

↓

BUSINESS
Structured capability presentation

↓

PROJECTS
Image-led evidence

↓

EXPERTISE / PROOF
Numbers, capabilities, or organizational evidence

↓

INSIGHTS
Editorial content

↓

CONTACT CTA
Strong closing statement
```

The homepage should feel like a **corporate introduction**, not a catalog.

---

# 16. About Visual Direction

The About page should feel more editorial and reflective.

Use:

* Large narrative typography
* Historical imagery where available
* Structured timeline/storytelling
* Mission/vision/value sections
* Human organizational photography

Avoid turning the page into a collection of icon cards.

---

# 17. Leadership Visual Direction

Leadership should emphasize people.

Use:

* Strong portrait photography
* Generous image proportions
* Clear names and roles
* Minimal card decoration

A leadership page should feel closer to an institutional profile than a social-media team grid.

---

# 18. Business Visual Direction

Business pages should feel structured and capable.

Use:

* Strong category labels
* Capability-focused typography
* Clear grids
* Project imagery
* Supporting technical/contextual information

Business Unit Detail pages should feel more substantial than the listing.

---

# 19. Projects Visual Direction

Projects should be among the most visually compelling pages.

Use:

* Large project photography
* Strong image crops
* Minimal card decoration
* Clear metadata
* Editorial project layouts

Avoid excessive rounded cards and generic portfolio thumbnails.

---

# 20. Project Detail Visual Direction

The project detail page should feel like a professional case study.

Recommended visual hierarchy:

```text
PROJECT TITLE
        ↓
HERO IMAGE
        ↓
PROJECT FACTS
        ↓
PROJECT STORY
        ↓
IMAGE / CONTENT SEQUENCES
        ↓
OUTCOME
```

Photography should support the narrative rather than simply fill space.

---

# 21. Insights Visual Direction

Insights should feel editorial.

Use:

* Strong article titles
* Generous whitespace
* Clear metadata
* Controlled image usage
* Comfortable reading width

Avoid making the Insights page resemble a social media feed.

---

# 22. Article Detail Visual Direction

The article page should prioritize reading.

Recommended structure:

```text
CATEGORY
TITLE

Summary

Date / Metadata

Hero Image

────────────────

Article Content
```

The reading column should remain comfortably narrow.

Related content should appear after or beside the main content only where it does not disrupt reading.

---

# 23. Careers Visual Direction

Careers should introduce more human warmth without breaking the corporate identity.

Use:

* People photography
* Workplace imagery
* Strong organizational statements
* Clear opportunity presentation

The design should communicate:

> This is a serious organization, but it is made of people.

---

# 24. Contact Visual Direction

Contact should be intentionally simple.

Use:

```text
Large heading
Supporting statement
Contact information
Inquiry form
Location information
```

Avoid unnecessary visual complexity.

The visitor's goal is to communicate with Asterra, not explore decorative interactions.

---

# 25. Image Direction

Photography should prioritize **authenticity over generic corporate stock imagery**.

Preferred:

* Actual projects
* Actual facilities
* Actual leadership
* Actual teams
* Relevant environments
* Authentic working situations

If stock photography is required, it should feel realistic and contextually appropriate.

---

# 26. Image Composition

Images should be treated as part of the layout.

Possible treatments:

```text
Full Bleed
Editorial Crop
Split Layout
Contained Image
Image Grid
Large Feature Image
```

Avoid placing every image inside the same rounded rectangle.

---

# 27. Image Ratios

Use a small number of consistent image ratios.

Examples:

```text
Hero
16:9 or cinematic ratio

Project Card
4:3 or 3:2

Portrait
3:4

Insight Card
16:9 or 3:2
```

Exact ratios can be adjusted based on the actual image assets.

---

# 28. Borders and Radius

The design should favor relatively restrained geometry.

Use:

* Subtle borders
* Controlled corner radius
* Strong rectangular editorial compositions

Avoid excessive pill-shaped UI.

Pills should primarily be reserved for:

* Tags
* Categories
* Status indicators

---

# 29. Shadows

Shadows should be used minimally.

The visual system should primarily create hierarchy through:

* Spacing
* Contrast
* Scale
* Borders
* Image composition

rather than large floating-card shadows.

---

# 30. Buttons

Buttons should feel substantial but not oversized.

Primary CTA:

```text
┌────────────────────────┐
│    Contact Asterra →   │
└────────────────────────┘
```

Secondary actions can use lighter visual treatment.

Arrow indicators may be used consistently to communicate movement/navigation.

---

# 31. Interaction Design

Interactions should be subtle.

Examples:

### Project card

```text
Default
   ↓
Image / title emphasis
   ↓
Subtle movement or overlay
```

### Navigation

```text
Default
   ↓
Clear active/hover state
```

### Button

```text
Default
   ↓
Hover
   ↓
Pressed
```

Motion should reinforce interaction rather than become a visual performance.

---

# 32. Motion Timing

Animations should generally be short and restrained.

Avoid:

* Long page entrances
* Excessive stagger animations
* Continuous background movement
* Large transformations

Users should never feel that they are waiting for the design to finish animating.

---

# 33. Accessibility and Motion

Respect reduced-motion preferences.

When reduced motion is enabled:

```text
Complex animation
      ↓
Simple transition
```

or:

```text
Animation
      ↓
No animation
```

Content must remain fully accessible.

---

# 34. Responsive Visual Direction

### Desktop

Use:

* Large typography
* Multi-column layouts
* Strong imagery
* Asymmetric compositions

### Tablet

Use:

* Reduced typography
* Simplified grids
* Controlled image sizes
* More balanced layouts

### Mobile

Use:

* Single-column compositions
* Strong hierarchy
* Reduced spacing
* Readable typography
* Simplified navigation

Mobile should feel intentionally designed, not like a collapsed desktop layout.

---

# 35. Mobile Hero

Large desktop hero compositions should not simply scale down.

Desktop:

```text
Text       Large Image
```

Mobile:

```text
Text

Image

CTA
```

or:

```text
Image

Text
CTA
```

depending on the specific page.

---

# 36. Mobile Navigation

The navigation should become a compact mobile menu.

The mobile navigation should prioritize:

```text
About
Business
Projects
Insights
Careers
Contact
```

Avoid deep multi-level navigation unless the content structure requires it.

---

# 37. Performance-Conscious Visual Design

Visual ambition should not create unnecessary performance costs.

Priority areas:

```text
Hero images
Project galleries
Large photography
Fonts
Animation
Third-party scripts
```

The design should support:

* Responsive image delivery
* Proper image sizing
* Modern formats
* Lazy loading where appropriate
* Stable image dimensions
* Minimal layout shift

---

# 38. SEO-Conscious Visual Design

Visual design must preserve semantic content.

Do not:

* Put important text only inside images
* Use decorative headings instead of semantic headings
* Hide important content behind interaction unnecessarily
* Replace meaningful links with icon-only controls
* Create visual layouts that prevent logical content order

The rendered visual hierarchy and semantic document hierarchy should work together.

# 40. Component Visual Language

Reusable components should visually belong to the same system.

For example:

```text
Business Card
Project Card
Insight Card
Leadership Card
```

may have different compositions but should share:

* Typography logic
* Spacing logic
* Border logic
* Interaction behavior
* Image treatment principles

---

# 41. What Should NOT Be Standardized

The following should remain flexible:

* Exact hero composition
* Number of sections
* Image placement
* Project storytelling format
* Article layout
* About-page narrative
* Business-detail structure

The design system provides rules; it should not eliminate creative page composition.

---

# 42. Visual Quality Gate

Before approving a page visually, evaluate:

### Hierarchy

Can the visitor immediately identify the most important message?

### Composition

Does the page have a clear visual rhythm?

### Typography

Does the type system create meaningful hierarchy?

### Imagery

Does imagery contribute to credibility and storytelling?

### Consistency

Does the page belong to the Asterra system?

### Differentiation

Does it avoid looking like a generic template?

### Accessibility

Can the content be comfortably read and interacted with?

### Performance

Could the visual treatment create unnecessary loading or rendering costs?

---

# 43. Final Visual Direction

The intended Asterra visual language can be summarized as:

```text
             ASTERRA
                │
     ┌──────────┼──────────┐
     │          │          │
 Corporate   Editorial   Technical
 Authority   Character   Precision
     │          │          │
     └──────────┼──────────┘
                │
       Modern Professional
```

The website should communicate authority primarily through **clarity, evidence, typography, photography, and composition**, not through excessive visual effects.

**Status: APPROVED — Visual Foundation**

This specification is now the visual bridge between the Asterra design architecture and the individual page designs.

It establishes the visual language without prematurely locking every component to exact values before the actual visual design work.
